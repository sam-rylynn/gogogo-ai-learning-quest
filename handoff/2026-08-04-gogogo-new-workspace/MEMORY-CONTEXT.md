# GOGO GO 产品记忆与决策

## 长期方向

- 用户以后完全在 Codex 中学习，不依赖 Claude。
- HTML 是行动与进度层；Codex 是解释、评分、纠错和反馈层。
- 学习者按零基础设计，不能用最少内容赶进度。
- 课程必须先讲清概念、基础词义、工作流程、案例和失败边界，再出题。
- 题目深度不能超过书库实际教学深度。
- 判断题和选择题承担高频训练；每张课卡保留一段自己的理解表述。
- 每个重要英文术语需要可点击小词卡，包含翻译、逻辑、流程和常见位置。

## 当前学习产品结构

- 课程书库：输入完整知识。
- 重点笔记：训练前压缩复习。
- 本关训练：判断题、选择题和系统即时审核。
- 错题档案：聚合弱点并返回对应课卡。
- 间隔复训：延迟后重新抽题。
- Codex：只在需要解释、纠错和深度审核时介入。

## 内容标准

每张课卡至少应包含：

- 零基础定义。
- 中文与英文术语。
- 它解决什么问题。
- 输入、处理、输出。
- 正例、反例和边界。
- 常见错误。
- 与前后知识的连接。
- 一段学习者自己的理解表达。

## 视觉标准

- 保持 2D 像素公会氛围。
- 任务面板不能遮挡场景人物。
- 首页只显示当前关卡、当前 STEP、下一关预告和下一步动作，不重复完整流程。
- 学习弹窗标题不锁定，必须随内容滚走。
- 书库、训练、错题和重点笔记的字体、框架与交互语言统一。

## 进度存储边界

浏览器进度位于 localStorage，而不是 Git：

- `gogogo_ai_quest_v2`
- `gogogo_pixel_guild_v1`
- `gogogo_unified_learning_v1`

`file://`、`127.0.0.1` 和 GitHub Pages 是不同 origin，进度不会自动互通。源码交接包不包含浏览器 localStorage。需要迁移学习进度时，应从原页面复制学习快照，或单独设计显式导入导出功能。
